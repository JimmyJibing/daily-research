## 一、核心动态（5 条）

### 1. 🔥🔥 Anthropic 连发两弹 — Fable 5（6.9）+ Sonnet 5（6.30）重塑 AI 编程底层能力

Anthropic 在 6 月连续发布两个里程碑模型，直接改变 AI 编程工具的底层能力上限：

**Claude Fable 5（6 月 9 日 GA）：**
- Anthropic **首个公开发布的 Mythos 级模型**（此前 Mythos 级仅限政府/研究用途）
- 编程基准测试得分 **翻倍于 Opus 4.8**，达到"自主资深同事"水平——可连续数天处理一个问题、自主规划和验证工作
- 定价：$10 输入 / $50 输出（每百万 token），恰好是 Opus 4.8 的两倍
- 已接入 GitHub Copilot、Google Vertex AI 等平台
- 注意：Fable 5 是 Mythos 5 的"安全版"——加了安全分类器路由高风险请求到 Opus 4.8

**Claude Sonnet 5（6 月 30 日发布）：**
- 定位为 **"最具 Agent 能力的 Sonnet"**，在编程、工具使用、推理方面大幅改进
- 相比 Fable 5 的高价定位，Sonnet 5 更面向日常开发场景的成本敏感型选择
- 已迅速被 Cline、Cursor 等工具集成

**对 AI 编程工具格局的影响：**
- 所有 AI 编程工具的"智商天花板"被整体抬高——Fable 5 的推理能力意味着复杂重构任务可更依赖 AI
- 但成本也同步上升：Fable 5 输出价格 $50/M token，重度 Agent 使用月费可能破千美元
- Cursor / Cline / Copilot 等工具正在快速适配，新模型的集成速度成为竞争差异点

**对大土豆的影响：**
- **模型选择策略升级**：简单补全用 Sonnet 5 / 本地模型，复杂重构才用 Fable 5，需要建立"模型阶梯使用规范"
- 智能家居/TV 固件的复杂 C/C++ 代码重构场景值得用 Fable 5 试效果
- ⚠️ Fable 5 的高成本意味着需要更严格的 Token 预算管理

### 2. 🔥 Roo Code 正式关闭（5.15）→ 团队转向 Roomote — 开源 AI 编程第二波整合

继 Continue 之后，又一个重要的开源 AI 编程工具被关闭：

- **Roo Code** 于 **2026 年 5 月 15 日归档 GitHub 仓库**，安装量曾达约 300 万
- 团队转向开发新产品 **Roomote**（截至 6 月仍处于早期开发，未公开发布）
- Roo Code 曾以"模式驱动"（Architect/Code/Debug/Ask/Custom Modes）著称，是 Cline 生态的重要分支

**连锁反应：**
- **Kilo Code**（开源，Apache 2.0）成为 Roo Code 用户的自然迁移目标——它**自动读取 `.roomodes` 和 `.roo/rules/` 配置**，零迁移成本
- Cline 成为 VS Code 生态中最后一个大规模的开源 Agent 选项
- 社区出现了 **ZooCode** 等 Roo Code 风格的社区 fork
- 这一事件强化了上期报告的趋势判断：**AI 编程工具正从"百花齐放"走向"巨头整合"**

**对大土豆的影响：**
- 如果团队中有使用 Roo Code 的开发者，推荐立即迁移到 Cline 或 Kilo Code
- Roo Code → Kilo Code 迁移最平滑（配置自动兼容）
- Roo Code 关闭 + Continue 关闭 = **开源 AI 编程工具的生存危机**，选择工具时"团队存续性"成为关键评估维度

### 3. 🔥🔥 Microsoft Build 2026 — Windows 正式成为 AI Agent 原生平台

6 月初的 Microsoft Build 2026 是 Windows 平台 AI 编程生态的转折点：

**五大关键发布：**

| 发布项 | 说明 |
|--------|------|
| **Windows Copilot Runtime** | 本地 NPU AI 推理 API，Agent 可直接在 PC 上运行本地模型 |
| **Windows Agent Runtime** | Agent 执行引擎，支持文件读写、应用操作、系统事件响应 |
| **Microsoft Execution Containers** | Agent 沙箱执行环境，隔离 AI 操作 |
| **Intelligent Terminal** | 新一代终端，深度集成 Copilot CLI |
| **Windows 365 for Agents** | 云端 Windows 实例，专为 Agent 工作负载设计 |

**核心变化：**
- Windows 不再是"被动操作系统"，而是 **Agent 编排层**：协调设备硬件（CPU/GPU/NPU）、本地模型、云端智能、企业策略
- **Local AI Agent API** 向开发者开放 NPU 直接访问——AI Agent 可以本地处理文件、文档、工作流，无需上传到云端
- **WSL 容器**即将公开预览——Linux 容器可直接在 Windows 上运行
- 配合 **Surface Laptop Ultra / RTX Spark** 等新硬件，本地 AI 推理能力大幅提升

**战略意义：**
- Microsoft 在 Build 2026 上的信息很明确：**"Agent 时代需要一个可信赖的 OS"**
- Windows 正在从传统桌面 OS 转型为"混合 AI 平台"：本地推理 + 云端扩展 + 企业治理
- 这对"AI PC"概念是第一次真正落地——之前的 Copilot+ PC 更多是营销，Build 2026 给出了开发者可用的 API

**对大土豆的影响（重点！）：**
- 🎯 **智能家居本地 Agent 场景**：Windows Agent Runtime 可以直接在测试 PC 上运行设备管理 Agent，无需云中转——这对智能家居本地化方案是重大利好
- 🎯 **TV 固件编译 Agent**：利用 NPU 在本地运行代码审查/编译优化 Agent，代码不出设备
- 🎯 **Windows 平台开发效率**：Intelligent Terminal + Copilot CLI 组合可显著提升 Windows 上的 C/C++/Java 开发体验
- ⚠️ 但生态仍在早期：API 刚发布，实际可用的第三方 Agent 还很少，建议保持关注但暂不做生产级投入

### 4. 🔥 Microsoft 内部强制 Copilot CLI 迁移（6.30 截止）— Windows 部门全部弃用 Claude Code

Microsoft 在 5 月做出一个震动行业的内部决策：

- **6 个月试用期后，Microsoft 要求 E+D 部门（Windows / Microsoft 365 / Outlook / Teams / Surface）工程师在 6 月 30 日前全面移除 Claude Code**
- 强制迁移到 **GitHub Copilot CLI**
- 表面理由：成本控制 + 与内部工作流深度集成 + 企业安全策略
- 深层原因：Claude Code 在内部"太受欢迎"——甚至吸引了设计师和项目经理等非工程师用户，Microsoft 需要"驯化"内部 AI 编程工具的使用

**行业信号：**
- 这是 **"AI 编程工具供应商锁定"的 textbook 案例**——Microsoft 不能容忍自己的工程师重度依赖竞争对手 Anthropic 的工具
- 也说明 Claude Code 的实际效果好到 Microsoft 觉得需要"强制禁止"
- 类似趋势在字节跳动也存在：字节内部从 2025 年 6 月 30 日起禁用第三方 AI 开发软件，全面采用 Trae

**对大土豆的影响：**
- **供应商锁定风险是真实存在的**——Microsoft 和字节跳动的做法说明，大型组织最终会选择"自己的工具"
- 对中立企业/研究所：**坚持多工具并行策略**，避免单一供应商依赖
- Cline（开源+模型无关）作为"中立底座"的价值进一步凸显

### 5. 🔄 Agent Skills 生态突破 930+ — 跨工具可移植技能包成为 AI 编程新标准

Anthropic 于 2025 年 12 月 18 日发布的 **Agent Skills 开放标准** 在 2026 年上半年迎来爆发：

**关键数据：**
- **930+ Agent Skills** 已发布，覆盖 Claude Code、Cursor、Antigravity、OpenAI Codex、VS Code 等 16+ 工具
- 一个 SKILL.md 目录可跨所有兼容工具使用——**"一次编写，到处运行"**
- 包含来自 Anthropic、Vercel 等官方的 Skills
- Cline 生态的 SKILL.md 社区也在增长（code-reviewer 447 安装、git-commit-writer 170 安装）

**Agent Skills 标准的核心机制：**
- 一个目录 + 一个 SKILL.md 文件 = 一个可移植的能力包
- SKILL.md 定义：技能描述、使用方式、行为规则
- 支持的工具自动加载并执行

**对大土豆的影响（重点！）：**
- 🎯 **智能家居/TV 垂直领域 Skill 包的时机已成熟**：AOSP TV 编译、Matter 协议、嵌入式交叉编译、多屏 UI 适配等场景完全可以打包为 Agent Skills
- 🎯 一套 Skill 可同时用于 Cline（本地安全编码）+ Trae（日常开发）+ Antigravity（实验），降低重复配置成本
- 建议：从最简单的场景（如 Git Commit 规范、代码审查规则）开始制作 Skills，逐步扩展到领域知识

## 二、技术趋势分析

### 1. AI 编程工具进入"模型军备竞赛 + 生态整合"双轮驱动

2026 年 6 月是 AI 编程工具的转折月：
- **模型侧**：Fable 5 + Sonnet 5 大幅提升了能力上限和成本上限
- **工具侧**：Roo Code 关闭 → 开源选项减少，巨头整合加速
- **平台侧**：Windows 成为 Agent 原生平台，AI 编程从"编辑器"升级为"OS 能力"
- **标准侧**：Agent Skills 达到 930+，跨工具可移植性成为现实

**结论**：AI 编程工具正在形成"三极三层"格局：
- **三极**：Cursor（AI 原生 IDE）、Antigravity（平台生态）、Trae（中国化）
- **三层**：模型层（Fable 5/Sonnet 5）、工具层（IDE/CLI/Agent）、平台层（Windows Agent Runtime）
- **开源底座**：Cline 成为唯一的大规模开源选项

### 2. Windows 平台 AI 编程生态迎来拐点

Microsoft Build 2026 是 Windows 平台 AI 编程能力的"iPhone 时刻"：
- 从"在 Windows 上运行 AI 工具"到"Windows 本身是 AI 平台"
- NPU 本地推理使代码安全敏感的智能家居/TV 场景有了本地化方案
- **对大土豆团队的特殊意义**：智能家居设备管理、TV 固件编译、本地测试等场景可直接在 Windows PC 上运行专用 Agent

### 3. 开源 AI 编程工具的"关闭潮"警示

Continue（6 月）+ Roo Code（5 月）接连关闭，共同特征：
- 都是基于开源社区起家的成功项目
- 都面临商业化压力或团队转型
- 用户被迫迁移

**教训**：选择开源工具时，"团队存续性"和"协议安全性"（Apache 2.0 最优）是最重要的评估维度。Cline 目前兼具两者（Apache 2.0 + 社区活跃 + GitHub 58,600+ Stars）。

## 三、企划洞察

### 💡 机会 1：基于 Windows Agent Runtime 的智能家居本地测试 Agent

Build 2026 发布的 Windows Agent Runtime 为智能家居场景提供了新的技术基础：

- **场景**：在测试 PC 上运行本地 Agent，自动部署固件到测试设备 → 执行自动化测试 → 分析结果
- **优势**：数据不出本地 PC，无需云中转；利用 NPU 加速推理
- **技术栈**：Windows Agent Runtime + NPU API + Cline + Ollama 本地模型
- **时机**：API 刚发布，适合做 POC 探索

### 💡 机会 2：Agent Skills 的智能家居/TV 领域包开发

Agent Skills 标准的成熟（930+）使得垂直领域技能包开发的门槛大大降低：

- **优先级 1** — AOSP TV 编译链 Skill：Android TV 系统编译、签名、OTA 打包
- **优先级 2** — Matter 协议代码生成 Skill：智能家居 Matter 标准的代码模板和验证
- **优先级 3** — 嵌入式交叉编译 Skill：ARM/RISC-V 工具链配置和构建
- **优先级 4** — 多屏 UI 适配 Skill：TV + 手机 + 手表的响应式设计规则

建议从优先级 1 开始，用 Cline SKILL.md 格式做 MVP。

### 💡 机会 3：模型阶梯策略 — 降低 AI 编程成本

Fable 5 ($50/M output tokens) 的发布使得"模型选择策略"从 nice-to-have 变成 must-have：

- **Tier 1（免费）**：简单补全 → Trae 免费版 / Cline + Ollama 本地模型
- **Tier 2（低成本）**：日常编码 → Cline + Sonnet 5 / DeepSeek V4
- **Tier 3（高性能按需）**：复杂重构、跨文件分析 → Claude Code + Fable 5 / Cursor Ultra
- **预算计划**：人均月 AI 编程费用控制在 $20-50（不含 Fable 5 重度使用）

### ⚠️ 风险提示

1. **Roo Code 用户需立即迁移**（仓库已归档），推荐 Kilo Code（配置自动兼容）或 Cline
2. **Fable 5 成本失控风险**：$50/M output tokens，重度 Agent 使用月费可能远超预期
3. **Microsoft 垄断风险**：Windows Agent Runtime 可能深度绑定 Azure/Copilot 生态，需评估锁定程度
4. **Agent Skills 碎片化**：虽然标准统一，但不同工具的实现可能不兼容，需要实际测试
5. **Antigravity 2.0 仍无 GA 日期**，不可用于生产
