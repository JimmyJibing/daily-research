### 3. Anthropic "Context Engineering" 新方法论 — Claude Code 系统提示词削减 80%+ ⭐️⭐️⭐️

| 项目 | 内容 |
|------|------|
| **来源** | Anthropic 官方博客（2026-07-24） |
| **PM技能** | product-strategy |

Anthropic 公开发布了针对 Claude 5 代模型（Opus 5、Fable 5）的 **Context Engineering 新规则**，核心发现：**Claude Code 的系统提示词可以减少 80% 以上，编码评估无任何可测量的性能损失。**

**六大方法论转变：**

| 旧做法 | 新做法 |
|--------|--------|
| 给 Claude 规则（Rules） | 让 Claude 使用判断力（Judgement） |
| 一次性全部前置（Put it all upfront） | 渐进式披露（Progressive Disclosure） |
| "不要写注释/文档" 强指令 | 匹配周围代码风格决定注释密度 |
| CLAUDE.md 承载一切 | 按需加载 Skills、Memory、Artifacts |
| 系统提示词承载所有约束 | 工具描述/选择性 Skills 承载 |
| 通用一刀切规则 | 项目特定的"陷阱"提示 |

**产出转移：**
- 验证和代码审查信息 → 放入独立 Skills，Claude Code 按需调用
- 部分工具定义 → 延迟到 Agent 搜索时才加载
- 项目级 `CLAUDE.md` → 聚焦"代码库特有陷阱"而非通用知识

**🫘 分析：** 这是 AI 编程工具设计哲学的重大转变。"Unhobbling Claude"（解除对 Claude 的束缚）意味着更强的模型不再需要保姆级指令。这对所有依赖系统提示词控制 Agent 行为的编程工具（Cursor Rules、Copilot Instructions、Codex Config）都有参考价值——"少即是多"的思路可能成为新的设计范式。值得注意的是，这一策略**仅适用于 Claude 5 代模型**，更老的模型（Opus 4.x、Sonnet 4）仍需要完整提示词。

**与已有报告对比：** 全新内容。此前未从系统提示词设计角度分析 AI 编程工具。

### 1. Vibe Coding vs Vibe Engineering — 概念分化 ⭐️⭐️

| 项目 | 内容 |
|------|------|
| **来源** | Rocket.new / Alex Klos / Simon Willison（2026-07-24） |

开发者社区正在将"vibe coding"这个宽泛概念分化为两个不同的实践：

| 维度 | Vibe Coding | Vibe Engineering |
|------|-------------|-----------------|
| 起点 | 自由提示 | 规格说明（spec） |
| 代码审查 | 可选/跳过 | 每次变更必须 |
| 测试覆盖 | 最少/无 | 合并前必须 |
| 架构 | 涌现式、混乱 | 定义并强制执行 |
| 调试 | 把错误反馈给 AI | 阅读、理解、修复 |
| 所有权 | 无特定人 | 指名的团队成员 |
| 规模上限 | 个人项目/MVP | 团队级生产环境 |

**术语来源：**
- "Vibe coding" — Andrej Karpathy（2025年2月）
- "Vibe engineering" — Simon Willison（2025年末）

**产业影响：** 这一概念分化对编程工具的产品设计有直接影响。工具正在根据用户所处的模式提供不同程度的结构化支持——Claude Code 的 plan mode、Cursor 的 Composer "Plan & Approve"模式、Windsurf 的 Cascade 逐步审批，本质都是在"vibe engineering"方向增加护栏。

### 2. Vibe Coding 安全数据深化 — 量化风险 ⭐️⭐️

| PM技能 | swot-analysis |

近期多个研究和报告提供了更具体的 vibe coding 安全风险量化数据：

| AI 生成代码样本中 **45%** 含 OWASP Top 10 漏洞 | Veracode | 持续 |
| AI 辅助开发者提交速度 **3-4x**，安全发现速度 **10x** | CSA AI Safety Initiative（Fortune 50） | 2026 |
| 企业违规事件中 **20%** 由 AI 生成代码导致 | SQ Magazine | 2026 |

**关键攻击向量：**
- **Slopsquatting**：攻击者注册 AI 幻觉出的包名，等待开发者安装
- **默认开放架构**：AI 倾向于生成无认证的 API 端点
- **服务账号权限过度**：AI 容易赋予"访问令牌创建者"等危险角色

**Thoughtworks 实例（07-24 报道）：** 一个 vibe-coded 视频组装原型在扩展至 10,000 员工时发现两项致命安全问题：AI 建议将云存储桶设为公开、赋予服务账号过高权限。

**与已有报告对比：** 上期报告未涉及 vibe coding 安全数据的深度量化分析。这些数据将成为后续讨论的参考基准。

美国联邦法官 Araceli Martínez-Olguín 于 **2026-07-20** 对 Bartz v. Anthropic $15 亿版权集体诉讼和解协议做出**最终批准**。

**关键细节：**

| 项目 | 数值 |
|------|------|
| 和解总金额 | **$15 亿** |
| 涉及作品数 | 482,460 部 |
| 索赔率 | **92.77%** |
| 每部作品平均赔偿 | **~$3,100** |
| 律师费 | $101.6M（从申请的 $187.5M 削减 $86M） |
| 首批付款预期 | **2026-08-10**（暂定） |

**里程碑意义：**
- 美国历史上**最大**版权和解案
- 确立 AI 训练版权侵权的 **$3,100/作品** 司法基准——这个数字将成为所有后续 AI 版权诉讼的参考锚点
- **强制销毁**所有盗版训练数据及衍生副本——不只是赔钱了事
- 仅 ~350 人选择退出（opt-out），继续单独起诉

**区分：**
- 和解针对的是**盗版获取**（通过 LibGen、PiLiMi 下载）行为，不是泛化的 "AI 训练 = 侵权" 问题

**对 OpenAI 的后续影响：** 法院已要求 OpenAI 提供 2,000 万条匿名化 ChatGPT 日志。如果其中包含大规模侵权证据，以每个作品 $3,100 计算，潜在赔偿责任可能远超 Anthropic 和解金额。

**与已有报告对比：** 上期报告提到和解金额但未覆盖最终批准、$3,100/作品基准、销毁令等细节。
