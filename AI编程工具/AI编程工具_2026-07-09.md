## 一、本月关键更新

### 1. MCP 协议 2026-07-28 RC 发布：史上最大规模重构 | 🔥 协议层「去状态化」革命

**摘要：** 7月初，MCP 发布了 2026-07-28 Release Candidate，这是自 2024-11-05 初版以来最大规模的协议重构。核心变更：① **彻底去状态化**——移除 `initialize` 握手和 `Mcp-Session-Id`，每个请求自带 `_meta` 携带协议版本、客户端身份和能力声明；② **`server/discover` 新 RPC**——服务器必须实现此端点，客户端可在任何请求前探测版本和能力；③ **MRTR（多轮往返请求）模式**——取代旧的服务器发起请求（`roots/list`、`sampling/createMessage`），服务器返回 `InputRequiredResult`，客户端重试时附上 `inputResponses`；④ **Tasks 正式扩展**——从核心协议移入 `io.modelcontextprotocol/tasks` 扩展，改用 `tasks/get` 轮询替代阻塞式 `tasks/result`；⑤ **`subscriptions/listen`**——统一的长连接通知流取代旧的 SSE GET 端点 + `resources/subscribe`；⑥ **缓存标准化**——`tools/list` 等返回 `ttlMs` + `cacheScope`，提升 LLM prompt cache 命中率。

**参考价值：** ① 去状态化意味着 MCP 服务器可以用无服务器函数（Lambda/Cloudflare Workers）实现，部署成本大幅降低，对智能家居后端服务的工具集成是重大利好；② MRTR 模式让 Agent 可以在一次请求中向用户索要多轮输入（确认/选择/补充），交互体验更自然；③ Tasks 扩展正式化意味着长时间运行任务（如固件编译、OTA 构建）有标准化的异步模式；④ 建议团队关注 SDK 适配进度，7/28 正式发布后及时升级。

### 2. Cursor 全平台扩张：iOS App 公测 + Team MCPs + Automations 2.0 | 📱 IDE → 移动+云 Agent 平台

**摘要：** 6月下旬-7月初，Cursor 密集发布多项重大更新：① **Cursor for iOS 公测**（6月底）——所有付费用户可用的原生 iOS App，支持从手机启动 Cloud Agent、语音输入、Remote Control 远程控制桌面 Agent、Live Activities 锁屏追踪、推送通知、直接在手机上审查 Diff 和合并 PR。Cloud Agent 运行在隔离 VM 中可长时间自主工作；② **Team MCPs**——管理员可配置一次 MCP 服务器，统一分发到 Cloud Agent、Agent Window、IDE 和 CLI，团队成员无需自行配置；③ **Automations 大幅增强**（6/18）——新增 `/automate` skill（自然语言创建自动化）、Slack emoji 触发器、5 种新 GitHub 触发器（Issue comment / PR review comment / PR review submitted / Review thread updated / Workflow run completed）、Cloud Agent 支持 computer use 工具输出 Demo；④ **Customize 统一页面** + **Team Marketplace 扩展**——支持 GitLab/BitBucket/Azure DevOps 导入插件，organization groups 权限控制，Marketplace 排行榜。

**参考价值：** ① iOS App + Cloud Agent 的组合让开发者可以在手机上启动和管理编程任务——这意味着可以在任何场景响应紧急需求，对团队 on-call 场景极有价值；② Team MCPs 的"一次配置、全团队分发"模式值得借鉴，如果团队内部自建 MCP 工具（如设备管理 API、测试平台），可以参考此模式做统一分发；③ Automations 的 computer use 能力（Agent 操作浏览器出 Demo）可能适用于智能家居 App 的自动化 UI 测试和验收；④ 注意：Cursor 正在从"编辑器"转型为"Agent Platform"，这个趋势值得持续跟踪。

### 3. Cline v3.0.35-v3.0.39 / v4.0.5-v4.0.7：ClinePass 全面开放 + UI 重设计 + 模型生态扩展 | 🎨 Plan/Act 双模式正式成型

**摘要：** 6月下旬-7月初，Cline 快速迭代：① **ClinePass 全面开放**（v4.0.3-v4.0.7）——移除 feature flag，所有用户可用，支持免费模型和用量计费切换，移除 GLM 5.1；② **Claude Sonnet 5 全平台支持**（v4.0.5）——覆盖 Anthropic / Bedrock / Vertex / Claude Code / SAP AI Core / OpenRouter / Vercel AI Gateway 七个 provider；③ **Plan/Act 模式 UI 重设计**（v3.0.38）——Act 模式蓝色 (#79b8ff)、Plan 模式琥珀色，应用于对话框、模型选择器、配置、Markdown 语法高亮，chat input 也进行了极简重设计；④ **弱模型容错增强**（v3.0.37）——DeepSeek 等模型产生的畸形 tool call（错误参数类型、截断 JSON）被优雅处理而非报错；⑤ **Plan→Act 无缝切换**（v3.0.36）——修复 Plan 模式下 `switch_to_act_mode` 不能立即生效的 bug，切换后自动以 Act 模式继续执行已批准的计划；⑥ **新增 Tencent TokenHub 作为 provider**（v3.0.35）——国内开发者可通过腾讯云 TokenHub 接入。

**参考价值：** ① Plan/Act 双模式 + UI 色彩区分是很好的交互设计参考——在 AI 编程工具中显式区分"规划"和"执行"两个阶段，减少 AI 擅自改代码的风险；② 弱模型容错（DeepSeek）意味着团队可以用更低成本的模型做日常编码，只在复杂任务时切到 Sonnet 5；③ Tencent TokenHub 的加入对国内团队是利好，可能比直接走 Anthropic API 更稳定、成本更低；④ ClinePass 免费模型对大土豆团队评估 AI 编程工具降低了门槛。

### 4. Trae Work：Design Mode 设计稿转代码 + BytePlus Pages 一键部署 | 🚀 从设计到部署的全链路闭环

**摘要：** 6月 Trae 完成了重大品牌升级和功能扩展：① **Trae Work 发布**（6/9）——Trae SOLO 更名为 Trae Work，新增企业账号登录，定位从"个人 AI 编程助手"升级为"团队 AI 工作平台"；② **Design Mode 上线**（6/25）——支持设计稿（Figma 等）一键转换为代码，支持批量自然语言编辑修改；③ **Trae Work × BytePlus Pages**（7月初）——集成字节跳动 BytePlus Pages 服务，"描述即部署"——描述需求后 Agent 生成代码并直接部署上线，生成可分享链接；④ **语音对话持续增强**——支持最小化后台运行、拍照和文件共享。

**参考价值：** ① Design Mode + 设计稿转代码对智能家居 App/TV 界面的 UI 开发效率极高——设计师出 Figma 后开发者直接生成前端代码，减少手工切图工作量；② "描述→生成→部署→分享链接"的全链路闭环是目前 AI 编程工具中最完整的，PM 和设计师也能直接产出可交互原型；③ Trae 完全免费 + 中文优化 + 企业账号，对国内团队是 Cursor/Copilot 的最强替代方案；④ 建议团队实际试用 Design Mode，用现有智能家居 App 的设计稿测试代码生成质量。

---

### 5. Cursor Automations 2.0：事件驱动 Agent 进入「全自动」阶段 | ⚡ 代码审查、CI 失败自动修复

**摘要：** 6月18日 Cursor Automations 重大更新（因重要性单列）：① **`/automate` skill**——在 Agent 会话中用自然语言描述任务即可自动创建自动化规则（配置触发器、指令、工具），无需手动编写配置；② **Slack emoji 触发器**——对 Slack 消息回复指定 emoji 即可触发自动化；③ **5 种新 GitHub 触发器**——Issue comment、PR review comment、PR review submitted、Review thread updated、Workflow run completed，加上原有 PR/Issue 触发器，几乎覆盖了 GitHub 上的所有协作事件；④ **Computer use for automations**——Cloud Agent 可操作浏览器产出 Demo 截图/录屏作为工作产物；⑤ **预置模板**——自动分类 GitHub Actions 失败、自动修复 PR review comments。

**参考价值：** ① "自动修复 PR review comments"和"自动分类 CI 失败"两个场景直接提升团队开发效率——减少开发者在 CI 失败排查和简单 review 修改上的时间；② Slack emoji 触发意味着非技术人员（PM/设计师）也能通过 Slack 消息触发 Agent 工作（如"生成周报"、"更新 API 文档"）；③ Computer use + automations 组合可能在智能家居设备的自动化测试中有应用前景——Agent 自动打开设备管理后台、截图、对比 UI 变化；④ 事件驱动 Agent 正在成为 AI 编程工具的标配能力（Cursor Automations → GitHub Copilot Agent → Cline 生态），建议团队评估工作流中哪些环节适合接入。

## 二、趋势总结

| 趋势 | 信号 | 影响评估 |
|------|------|----------|
| **协议去状态化** | MCP RC 彻底移除 session/initialize，每个请求自包含 | 降低 MCP 服务器部署门槛，Serverless 友好 |
| **IDE → Agent Platform** | Cursor 出 iOS App、Team MCPs、Automations；Trae Work 品牌升级 | AI 编程工具不再只是"编辑器插件"，而是全平台 Agent 管理中心 |
| **Plan/Act 双模式成为标配** | Cline 重设计 Plan/Act UI；Cursor 有 Yolo/Plan 模式；Copilot 有 Canvases 双向交互 | 行业共识：AI 编程需要显式区分"规划"和"执行" |
| **事件驱动自动化** | Cursor Automations 2.0 覆盖 GitHub+Slack；Copilot App 从 Issue 启动 Agent | "AI Agent 自动响应事件"正在取代手动触发 |
| **设计→代码→部署全链路** | Trae Design Mode + BytePlus Pages；Cursor Cloud Agent 产出 Demo | 从设计稿到可访问链接的完整闭环正在成型 |
