## 一、本期关键更新

### 1. Claude Code v2.1 系列大更新：Auto-Mode 增强 + 工作流架构重塑 | 🤖 CLI Agent 进入"自主决策"新阶段

**摘要：** Claude Code 在 7 月上旬密集发布 v2.1.191+ 版本，核心变化：① **Auto-Mode 权限精细化**——新增拒绝原因记录到 transcript、`/permissions recent denials` 查看拒绝历史，权限模式默认值从 `default` 改为 `Manual`（更安全）；② **Dynamic Workflow Size**——`/config` 中新增工作流规模设置（small/medium/large），控制 Agent 数量，不是硬上限而是建议性指导；③ **`/rewind` 支持**——可在 `/clear` 之后恢复对话，Coding Agent 的会话容错性质变；④ **Remote Control 修复**——修复移动端/Web 端发送的图片和文件被静默丢弃的问题，`/remote-control` 权限模式显示修正；⑤ **MCP 错误信息改善**——当 Server 配置缺少 type 时正确提示 `type: "http"` 而非误导信息；⑥ **Sonnet 5 集成优化**——Sonnet 5 不再在对话中使用 mid-conversation system role 发送 harness 提醒。另外 `@cline/sdk` 成为 Cline SDK 的核心 Agent 运行时，Claude Code 的工作流架构正在与开源生态互相渗透。

**参考价值：** 对大土豆团队：① Auto-Mode 的权限精细化使 AI Agent 在 CI/CD 管道中更安全的自主运行——TV/手机固件的自动化构建和测试流水线可以嵌入 Claude Code 作为"自主修 bug Agent"；② Remote Control 修复意味着移动端指挥 Agent 的体验趋于可用，管理者可通过手机随时介入 Agent 工作；③ Workflow Size 设置对大项目（如智能家居全栈 App）可平衡效率与成本。

### 2. Claude Fable 5 今日起退出订阅计划：Mythos 级模型进入"按需付费" | ⏰ 倒计时截止日

**摘要：** 今日（7月7日）是 Claude Fable 5 包含在 Anthropic 订阅计划中的最后一天。从明天起，Fable 5 将需要额外 AI Credits 才能使用。Fable 5 是 Anthropic 首个 Mythos 级公开模型，6月9日发布后被美国出口管制暂停3天，随后恢复但带限制。社区评价 Fable 5 为"无情地主动"（relentlessly proactive），编码能力显著超越 Opus 4.8，但消耗 2× Credits。这是 Anthropic 首次对旗舰模型实施"订阅外付费"策略，意味着顶级 AI 编程能力的成本正在分层。同时 Opus 4.8 和 Sonnet 5 仍然是订阅内主力模型。

**参考价值：** 对团队选型：① Fable 5 按需付费模式类似于"高级刀具"——在关键场景（复杂重构、架构设计）才启用，日常开发仍用 Sonnet 5；② 这反映了整个行业的定价趋势：AI 编程成本正在从"月费包干"向"按能力分层"转变，与 Copilot 的用量计价形成行业共振；③ 团队需要建立"模型选择策略"——什么样的任务用什么模型，这比"一刀切订阅"更经济。

### 3. Cline v3.81 + SDK 架构升级：从 VS Code 插件进化为"Agent 运行时平台" | 🏗️ 开源 Agent 的"内核"独立

**摘要：** Cline 从 v3.8 开始经历了一次根本性架构变革（当前 v3.81，61.2k Stars，500万+安装）：① **Cline SDK（`@cline/sdk`）成为核心运行时**——将 Agent harness 抽象为独立 npm 包，CLI 2.0、Kanban、VS Code 扩展、JetBrains 插件全部基于同一 SDK 层运行；② **ClinePass**——一键使用开放权重模型，内置 Onboarding、模型列表、订阅管理、组织授权和错误状态处理；③ **Customize Marketplace**——在 VS Code 扩展内直接发现和管理 Skills、MCP 服务器、Plugins，支持搜索过滤、安装/卸载、启用/禁用；④ **30+ 模型提供商**——新增 Fireworks GLM 5.2、Kimi K2.6 Fast、Kimi K2.7 Code、Qwen 3.7 Plus、MiniMax M3、SAP AI Core、LiteLLM、Codex OAuth 等；⑤ **通用 SDK Provider 设置**——更多提供商可共享同一模型选择器、推理控制、动态模型 ID。Cline 正在从一个"VS Code 扩展"转型为"Agent 运行时平台"，其 SDK 可以被嵌入 CI 管道、自定义脚本和第三方产品。

**参考价值：** 对团队技术架构：① Cline SDK 意味着可以在固件构建流水线中嵌入 AI Agent，不依赖特定 IDE——这对自动化程度要求高的 TV/手机固件团队极为重要；② Customize Marketplace 将 MCP/Skills 管理集成到 IDE 内，降低团队引入 AI 工具的门槛；③ 30+ 模型支持使团队可以灵活选择性价比最优的模型组合（如国内场景用 Kimi/Qwen，复杂任务用 Claude）；④ SDK 架构的开放性使自建 AI 工具链成为可能，不必被单一供应商锁定。

### 4. Cursor 推出 Automations + Cloud Subagents：Agent 从"按需调用"走向"常驻自动化" | ⚡ AI 编程的 Zapier 时刻

**摘要：** Cursor 7月初发布 **Automations**——一种始终在线的 Agent 自动化机制：① 新增 `/automate` 技能，Agent 可被 **GitHub Events**（PR 创建/Issue 更新）和 **Slack 消息**触发；② Cloud Agents 支持 **Computer Use**，可在云端虚拟机中操作浏览器和应用；③ **Cloud Subagents**——在独立 VM 上运行并行子 Agent，支持 PR babysitting（自动跟进 PR 审查意见并推送修复）和本地/云端无缝交接。结合此前的 iOS App 和 Remote Control，Cursor 正在构建一个"桌面写代码 → 云端持续跑 → 手机监控 → 事件触发自动化"的完整编程操作系统。这是 AI 编程工具的"Zapier 时刻"——从手动触发到事件驱动。

**参考价值：** 对团队开发流程：① GitHub Events 触发意味着 PR 提交后 Agent 可自动运行测试、审查代码、修复简单问题——开发者在睡觉时 Agent 仍在工作；② Cloud Subagents 的并行能力使大型项目（如智能家居 App 的多模块同时迭代）可以并行处理，大幅缩短集成周期；③ Slack 触发机制使非开发人员（PM、QA）也可以通过聊天触发 Agent 任务，打破"只有程序员才能驱动 AI 编程"的壁垒。

### 5. MCP Beta SDKs 发布 + 生态基建就绪：712天后，"MCP 2.0"进入可实施阶段 | 🔧 从规范到落地

**摘要：** MCP 官方博客宣布 **2026-07-28 规范候选版的 Beta SDKs 已发布**，这是 MCP 历史上最大的协议修订从"规范文本"走向"可运行代码"的关键里程碑。Beta SDKs 包含：① 无状态协议实现——服务器可用简单轮询负载均衡器扩展，不再需要 sticky session 和共享 session 存储；② Extensions 框架——通过反向 DNS ID 标识、能力协商、独立版本管理；③ MCP Apps 和 Tasks 扩展的运行时支持；④ OIDC 动态客户端注册的修正（`application_type` 声明）。社区反应积极，MCP 月下载量达 1.1 亿次，已超越 React 前3年的采用速度。MCP 已成为 ChatGPT、Claude、Perplexity、Grok、Mistral 等所有主流 AI 平台的集成标准。

**参考价值：** 对团队基础设施：① Beta SDKs 意味着现在就可以开始构建企业内部 MCP 服务器，等 7/28 正式发布时已完成适配——设备测试平台、CI 系统、项目管理工具都可以通过 MCP 接入 AI Agent；② 无状态架构使内部工具可以部署在 K8s Serverless（如阿里云函数计算），不再需要 sticky session 这头"运维怪兽"；③ MCP 作为行业标准的确立意味着内部工具的一次性投入可以对接所有主流 AI 编程工具（Cursor/Cline/Claude Code/Copilot），避免"为每个 IDE 写一次集成"的重复劳动。
