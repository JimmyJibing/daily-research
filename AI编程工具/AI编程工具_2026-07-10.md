### 1. Cursor 发布自研 Grok 4.5 模型：联合 SpaceXAI，从编码专家到通用智能体 | 🔥 编程工具厂商自研模型时代到来

**来源：** [Cursor Blog — Introducing Grok 4.5](https://cursor.com/blog/grok-4-5)（2026-07-08）

**摘要：** 7月8日，Cursor 联合 SpaceXAI 发布了自研 Grok 4.5 模型，这是 Cursor 首次发布面向「不止软件工程」的通用智能模型。核心亮点：① **MoE 混合专家架构**——使用数万亿 token 的 Cursor 交互数据进行训练，涵盖代码库操作、开发者-Agent 交互、科研论文、STEM 任务等广泛领域；② **强化学习驱动**——用分布式 Agent 系统批量构建高难度 RL 训练环境，确保模型学会"研究问题→使用工具→从错误中恢复→验证结果"的完整闭环；③ **相比前代 Composer 2.5（纯编码专家），Grok 4.5 刻意扩大训练数据面**，覆盖数据科学、金融、法律等知识工作；④ **全平台可用**——桌面端、Web、iOS、CLI、SDK，个人和团队套餐内含显著用量，首周双倍配额；⑤ **定价**——基础版 $2/$6 每百万输入/输出 token，快速版 $4/$18。Composer 2.5 继续保留并迭代。

**参考价值：** ① **编程工具厂商自研模型是重大趋势信号**——Cursor 不再满足于调用第三方 API，而是基于自身数据训练专属模型，这意味着 AI 编程工具的竞争进入"模型+平台+生态"三位一体阶段；② 对大土豆团队：Grok 4.5 的"跨领域知识工作"定位意味着它不仅能写代码，还能理解智能家居/TV/手机产品需求文档，辅助需求分析和技术方案评审；③ 训练数据中包含开发者-Agent 交互轨迹，说明 Cursor 的终极目标是让模型"像优秀开发者一样思考和行动"——这对团队中初级开发者的培养和代码质量把控有特殊价值；④ 建议关注后续 Grok 4.5 的基准测试结果，特别是 SWE-Bench/Terminal-Bench 等 Agent 能力指标。

### 2. VS Code 1.128 发布：多聊天 Agent 会话 + Copilot Vision 正式版 | 🤖 Agent 对话体验全面升级

**来源：** [VS Code 1.128 Release Notes](https://code.visualstudio.com/updates/v1_128)（2026-07-08）

**摘要：** 7月8日 VS Code 1.128 发布，Agent 对话能力迎来重大升级：① **Claude Agent 多聊天会话**——单个 Claude session 内支持多个聊天线程，可并行运行多个 Agent 任务（如主聊天开发 API、对等聊天同步写测试、分叉聊天探索替代方案），所有聊天共享一个 session 并在重启后恢复；② **无工作区快速聊天**——在 Agents Window 中无需打开工作区即可启动问答聊天，适合临时问题或快速咨询；③ **Copilot Vision 正式版**——可粘贴、拖放图片和 PDF 到聊天中，AI 理解视觉内容（UI 截图→代码修复、架构图→方案建议）；④ **子 Agent 只读聊天（预览）**——当 Agent 委托子 Agent 执行任务时，可实时查看子 Agent 的执行过程，但不干扰其工作；⑤ **OS 级键盘快捷键**——VS Code 未聚焦时也能触发命令（如全局呼出 Chat）。

**参考价值：** ① 多聊天 Agent 会话让"并行开发"成为可能——主开发者写功能、AI 同步写测试，或同时探索多个技术方案，效率直接翻倍；② Copilot Vision GA 对大土豆团队最有用的场景：截图 UI bug → AI 直接定位代码并修复；设计稿截图 → AI 理解布局结构；架构图 → AI 辅助技术评估；③ OS 级快捷键让 AI 助手真正"随时可用"，不需要切换窗口；④ VS Code 的 Agent 体验已从"聊天插件"进化到"多 Agent 并行协作平台"，建议团队升级体验。

### 3. Cursor Auto-review：用"分诊 Agent"管住 Agent 自主权 | 🛡️ 低风险放行、高风险拦截，不再弹窗轰炸

**来源：** [Cursor Blog — Governing agent autonomy with Auto-review](https://cursor.com/blog/agent-autonomy-auto-review)（2026-06-11）

**摘要：** Cursor 推出 Auto-review 安全机制——一个轻量级分类器 Agent，实时审查 Agent 的每步操作是否越界。核心设计：① **"转盘式"而非"开关式"**——低风险操作（如读文件、普通编辑）自动放行，高风险操作（如读密钥、操作生产系统、执行未知脚本）才拦截；② **上下文感知**——不仅看命令本身，还判断该操作是否符合用户意图（如 `python script.py` 是否安全取决于脚本内容，分类器可先用 ReadFile/Grep 检查）；③ **无缝运行**——与 Agent 在同一 RPC 流中运行，不增加延迟；④ **非阻断式反馈**——被拦截时不弹窗骚扰用户，而是给 Agent 反馈让它自己换更安全的路径；⑤ **训练数据**——基于 12 小时内部开发者会话，筛选出 6,122 条标注样本 + 合成高风险场景数据。

**参考价值：** ① 这是目前 AI 编程工具中**最优雅的安全管控方案**——解决了"频繁审批→用户麻木→跳过审查"的经典困境；② 对大土豆团队：如果团队使用 Cursor/Cline 等 Agent 工具，Auto-review 的理念（低风险自动放行、高风险才拦截）可以移植到团队自己的 Agent 安全策略中；③ 在智能家居/TV 固件开发场景中，Agent 操控设备或修改底层配置时的安全审查尤为重要，Auto-review 的分级管控思路值得参考；④ 小型分类器模型（小模型+推理）的实用化案例——不一定需要大模型做所有事情。

### 4. Cursor Bugbot 大幅提速：3x 更快 + 22% 更便宜 + 检出率提升 10% | 🐛 push 前自动 review，90% 任务 3 分钟内完成

**来源：** [Cursor Blog — Bugbot updates June 2026](https://cursor.com/blog/bugbot-updates-june-2026)（2026-06-10）

**摘要：** Cursor 的 AI Bug 检测 Agent（Bugbot）迎来重大性能升级：① **3 倍速度提升**——90% 的 Bugbot 运行在 3 分钟内完成；② **成本降低 22%**——归功于 Composer 2.5 模型驱动的 harness 优化；③ **检出率提升 10%**——每轮 review 发现更多 bug；④ **push 前运行**——通过 `/review` 命令在代码 push 之前运行 Bugbot 和 Security Review，提前发现和修复问题；⑤ **增量 review**——支持只 review PR 中新增的代码变更，避免重复审查已有代码；⑥ **智能去重**——如果你在本地跑了 `/review` 再开 PR，Bugbot 识别相同 diff 后跳过重复审查。

**参考价值：** ① Push 前自动 review 是一个极其实用的开发流程优化——在 CI 之前就捕获 bug，减少 CI 等待和反复提交；② 对智能家居/TV 软件团队：固件代码的 Bug 发现越早越好（一旦烧录到设备上修复成本倍增），Bugbot 的"push 前审查"模式可集成到开发工作流中；③ 22% 的成本降低来自模型训练改进而非降价——说明模型优化比单纯等 API 降价更可持续；④ 增量 review 功能让 AI 审查聚焦新增代码而非全量扫描，适合大型代码仓库。

### 5. Notion 集成 Cursor SDK：嵌入式 AI 编程 Agent 的产品化范式 | 🔌 3 周完成集成，Agent 从"工具"变为"被嵌入的能力"

**来源：** [Cursor Blog — How Notion used the Cursor SDK](https://cursor.com/blog/notion)（2026-06-25）

**摘要：** Notion 仅用数周就通过 Cursor SDK 将 AI 编程 Agent 嵌入其产品中：① **集成方式**——在 Notion 文档中 @Cursor、在讨论线程中提及、或分配 Issue，Cursor Agent 自动完成规划→构建→测试→验证→提 PR 的全流程；② **技术架构**——"Notion 线程 → Cursor Agent"的直接映射，每个消息触发一次 Agent run，通过 SSE 流式返回进度；③ **远程 MCP 支持**——通过 Cursor SDK 连接 Notion 自定义 MCP 服务器，让 Agent 实时读写 Notion 工作区；④ **Notion 工程师评价**："Cursor SDK 的形态与我们的模型几乎直接对齐，适配层非常薄"，"MCP 支持 + Cloud Sandbox + 工具使用——大部分 Agent 能力是开箱即得"。

**参考价值：** ① 这对大土豆团队有直接的启示——如果团队自建项目管理/需求管理/测试管理平台，是否也可以借鉴 Notion 的模式，通过 Cursor SDK 嵌入 AI 编程 Agent？② "Agent 从独立工具变成被嵌入的能力"是重要趋势——智能家居/TV 的 App 开发流程中，需求文档→AI 直接生成原型代码的效率提升可想象；③ 远程 MCP 是实现跨系统 Agent 协作的关键——团队自建的设备管理 API、测试平台可以通过 MCP 暴露给 Agent；④ Cursor SDK 的"薄适配"特性说明其设计已经成熟，第三方集成门槛低，值得评估。
