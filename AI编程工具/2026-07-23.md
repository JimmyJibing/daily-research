## 🔥 三、底层技术与协议 ⭐️

### 1. OpenAI 发布 Presence — 企业 Agent 部署平台 ⭐️⭐️

| 项目 | 内容 |
|------|------|
| **来源** | VentureBeat、OpenAI 官方博客（2026-07-22） |
| **PM技能** | product-strategy, competitive-brief |

OpenAI 正式发布 **Presence**，一个面向企业客户的 AI Agent 部署与管理平台。

**核心能力：**
- 一站式部署实时语音 Agent 和聊天机器人，覆盖客户服务和内部工作流
- 内置治理框架：公司知识库、SOP（标准操作程序）、审批动作、模拟测试、评估工具、护栏规则、人工升级规则
- Agent 仅获得任务所需的**最小权限**和信息访问（按需授权）
- 生产前模拟测试：可测试常见请求、边缘场景和高风险场景
- **使用 OpenAI 模型作为核心 Agent**，但允许客户通过 API 接入第三方模型和服务的护栏、工具和工作流
- 当前仅通过 OpenAI Forward Deployed Engineers（FDE）和选定系统集成商部署，**不提供自助服务**

**当前状态：**
- 有限 GA（General Availability），仅面向合格企业客户
- 首批支持实时语音和聊天体验
- 定价、地理限制、合同条款**未公开**
- 邮件和其他渠道支持"在路线图上"

**对 AI 编程工具的启示：**

| 维度 | 分析 |
|------|------|
| **OpenAI 策略转向** | 从"卖模型 API"转向"卖 Agent 解决方案"，Presence 是 OpenAI 的 enterprise platform play |
| **与 Codex CLI 关系** | Presence 面向通用企业 Agent（客服、工单），Codex CLI 面向编程专用 Agent。两者互补但共享底层治理理念 |
| **与 AHP + MCP 生态关系** | Presence 目前是封闭平台（核心用 OpenAI 模型），与 AHP（跨客户端共享 Agent 会话）和 MCP（Agent ↔ 工具标准）的开放理念形成对比 — OpenAI 选择"方案集成"而非"协议标准化" |
| **企业 Agent 安全参考** | Presence 的"按需授权 + 护栏 + 人工升级"设计可被 AI 编程 Agent 工具借鉴（Claude Code 已有类似机制，Codex CLI 待观察） |

**与已有报告对比：** 全新内容。OpenAI 在企业 Agent 平台的布局此前未系统覆盖。

### 2. Kimi K3 权重开源倒计时 ⏰ + 白宫新指控 ⭐️⭐️

| 项目 | 内容 |
|------|------|
| **Kimi K3 权重开源** | 2026-07-27（倒计时 4 天）🔥 |
| **MCP 1.0 正式发布** | 2026-07-28（倒计时 5 天）⏰ |

**白宫新指控（2026-07-22）：**
- 白宫科技政策办公室主任 Michael Kratsios 在 X 上发文，指控 Moonshot 在**泰国**访问了受限的 Nvidia **GB300** 处理器来训练 Kimi K3
- 同时指控 Moonshot **蒸馏（distill）Anthropic 的 Fable 模型**来构建 Kimi K3
- 此指控的时间节点敏感：距 Kimi K3 权重开源（07-27）仅 5 天

**对 AI 编程工具的影响分析：**

| 层面 | 影响 |
|------|------|
| **芯片管制** | 如果 GB300 确实经泰国流向中国 AI 公司，美国可能进一步收紧东南亚中转管控 → 影响中国编程模型的训练能力 |
| **模型蒸馏争议** | 蒸馏闭源模型用于开源发布涉及知识产权和 TOS 问题，可能引发 Anthropic 采取法律行动 |
| **开源发布风险** | 白宫在权重发布前 5 天抛出指控，不排除政策层面施压延迟或阻止发布的意图 |
| **企业采用影响** | 三星等跨国企业如果考虑使用 Kimi K3 进行代码开发，需关注此争议的后续发展（出口管制合规风险） |

**与已有报告对比：** 07-20 报告覆盖 Kimi K3 发布，07-22 补充了 Poolside 打破中国开源垄断，本期新增白宫层面的芯片溯源指控。

- 对编程工具（Cursor/Continue/Cline）而言：Gemini Flash 系列是非常有吸引力的"中低复杂度编程任务"候选模型

### 2. Reddit 可能切断 Google 数据供给 — 编程训练数据影响

| 项目 | 内容 |
|------|------|
| **来源** | WSJ / The Verge（2026-07-22） |
| **PM技能** | porters-five-forces |

- Reddit 与 Google 的 **$6,000 万/年**数据授权协议即将到期
- Reddit 高管正评估是否继续向 Google 提供数据用于 Gemini 训练
- 背景：AI 生成的搜索结果摘要减少了外链点击，Reddit 的 Google 搜索流量下降
- **Reddit 是代码讨论和编程问答的重要来源**（r/programming、r/MachineLearning 等），如果切断数据供给，将影响 Gemini 的编程相关训练数据质量

**对 AI 编程工具的间接影响：**
- 编程模型的训练数据来源正在收紧 → 高质量代码讨论数据可能变得更稀缺
- Stack Overflow（已与 OpenAI 合作）和 Reddit（正评估退出 Google 合作）的不同选择，正在重塑编程训练数据的供给版图
- 开源编程模型（Kimi K3、Laguna S 2.1）的独立数据采集能力变得更加重要

**与已有报告对比：** 全新内容。

### 3. OpenAI Presence 对 AI Agent 商业模式的影响

OpenAI Presence 的发布标志着 AI Agent 商业模式的重要转折：
- OpenAI 正从"基础设施供应商"（模型 API）向"解决方案集成商"（Presence 平台）延伸
- 这与 Microsoft 的 Copilot + AHP、Anthropic 的 Claude Code + MCP 形成 **三条不同的企业 Agent 路径**：

| 厂商 | 路径 | 开放性 | 目标客户 |
|------|------|--------|----------|
| **OpenAI** | Presence 集成平台（FDE 交付） | 封闭（核心用 OpenAI 模型） | 大型企业 |
| **Anthropic** | Claude Code + MCP 生态 | 开放协议 | 开发者 + 企业 |
| **Microsoft** | Copilot + AHP 协议 | 半开放（开源协议 + 商业产品） | 开发者 + 企业 |
